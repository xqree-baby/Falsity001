分法：按 HTTP 语义（老大 Day 23 拍板）　·　验证方式：真起服务打真请求，14 项全过　·　时间：2026-10-09 18:52

今天改的是哪句？——答：把三处「裸报错」换成人话

改前用户页面上会出现 not found、TypeError: Failed to fetch、relation "public.posts" does not exist 这类英文。现在全部换成中文，并且技术原文挪到detail 字段供开发者查。
类别errorCode用户看到的中文状态码
第一类
你传的不对		BAD_REQUEST你提交的内容有问题，请检查后再试一次。400
第二类
要找的没有		NOT_FOUND没找到要找的内容，它可能已经被删掉了。404
第三类
我们这边坏了		SERVER_ERROR服务器出错了，请稍后重试。500
DB_UNREACHABLE服务器暂时连不上数据库，请稍后重试。502
NOT_CONFIGURED服务还没配置好，请稍后重试。503
为什么要 errorCode：前端要区分「是我的错」还是「服务器的错」，不能去猜中文文案长什么样。中文给人看，code 给机器看。

改前 vs 改后 · 真跑实测输出

起了一个本地假数据库（故意返回英文技术报错），再打真 HTTP 请求拿到的真实响应体。
改前404 路由没匹配上
{"ok":false,"error":"not found","receivedPath":"/anything-not-matched"}
改后
{"ok":false,"error":"没找到要找的内容，它可能已经被删掉了。","errorCode":"NOT_FOUND","detail":"no route for /anything-not-matched"}
改前数据库报错（最刺眼的一条，整句英文甩到页面上）
{"ok":false,"error":"数据库 REST API 返回 400：{\"code\":\"42P01\",\"message\":\"relation \"public.posts\" does not exist\"..."}
改后
{"ok":false,"error":"服务器暂时连不上数据库，请稍后重试。","errorCode":"DB_UNREACHABLE","detail":"数据库 REST API 返回 400：{\"code\":\"42P01\",..."}
注意 detail 里英文原文还在——没扔掉，只是挪走了。页面上给用户看的是中文，出问题时开发者看 detail 照样能定位。
改前服务没配置好
{"ok":false,"error":"CLOUDBASE_API_KEY 未配置（在云函数环境变量里加 CLOUDBASE_API_KEY）"}
改后
{"ok":false,"error":"服务还没配置好，请稍后重试。","errorCode":"NOT_CONFIGURED","detail":"CLOUDBASE_API_KEY 未配置..."}

前端也改了：不然英文还在屏幕上

后端改完只是治了后端那些报错。浏览器端的 fetch 失败照样会把英文怼到页面上，所以四个页面各加了一个翻译函数。
浏览器报的英文改成的中文
TypeError: Failed to fetch连不上服务器，请检查网络后重试
timeout / abort服务器响应太慢了，请稍后重试
Unexpected token < in JSON服务器返回的数据格式不对，请稍后重试
r.status（裸数字 500）服务器返回 500，请稍后重试
英文原文不丢，落到浏览器控制台（console.warn），页面上不再出现。
