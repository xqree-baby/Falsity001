# 发布前检查（release-check）

检查对象：本仓库「发布出去之前」的状态。不是功能测试，是**发布前的闸门**。

## 铁律：没验证过「故意弄坏」的 Skill，不许被当作通过证据

一个检查工具最危险的不是漏报，而是**虚报通过**——查不出问题却报告「全部通过」。
漏报你会怀疑，虚报你会直接信。所以本 Skill 的可信度**不是自证的**，必须靠一次反向验证：

> **故意注入一个已知问题 → 跑本 Skill → 它必须报警 → 修掉 → 再跑 → 必须干净。**
> 「坏的时候报警、好的时候安静」两头都成立，才算这个 Skill 可信。
> 没做过这个验证就引用本 Skill 的「全部通过」，等于没查。

Day 25 建 Skill 时的验证记录见`RUN_LOG.md`。

## C1 密钥泄漏

### 为什么这么查

只看关键词会疯狂误报。本仓库 `API_KEY` 字样出现 9 处，**全部干净**：
`process.env.CLOUDBASE_API_KEY`（取变量名）、`Bearer ${API_KEY}`（运行时填值）、中文提示里的 `'CLOUDBASE_API_KEY 未配置'`。

所以判定条件是 **「变量名旁边有没有一个像密钥的字面量」**，不是「有没有出现变量名」。

### 三条通过标准（全部满足才算过）

1. **没有任何 `.env` / `.env.*` 文件被 git 跟踪**——用 `git ls-files` 查，查得到就是泄漏
2. **全仓库扫描密钥变量名 + 字面量的组合，命中 0 条**
3. 工作区里存在的 `.env` 文件处于被忽略状态

### 明确不算泄漏的写法（不许误报这些）

- `process.env.XXX` —— 取变量名，不是值
- `Bearer ${XXX}` —— 模板字符串
- 错误提示文案里提到变量名
- 明显标注为假值的测试桩，如 `"local-test-not-a-real-key"`、`"test"`

### 怎么算泄漏（会报警）

- `SECRET_KEY = "AKID8f3k2j..."` 这类变量名后紧跟一段像密钥的**字面量**
- `.env` / `.env.local` 被 `git add` 过、出现在 `git ls-files` 里

### 检查范围

扫：`*.js` `*.mjs` `*.cjs` `*.html` `*.json` `*.md`
排除：`node_modules/`、`.git/`、`.workbuddy/`、本Skill 自己的输出目录

## C2 公网可达性

### 为什么这么查

这个项目最阴的坑是「**后端活着但前端拿不到**」。Day 20 跨域头配了两遍，浏览器网络层把响应掐掉，前端只拿到 `Failed to fetch`，连状态码都读不到——看着像后端挂了，实际后端好好的。

### 两条通过标准（全部满足才算过）

1. 接口域名可达：`GET {API_BASE}/posts` 返回 HTTP 200，且返回体是合法 JSON
2. **响应头里只有一个 `access-control-allow-origin` 值**（逗号拼接成两个 = 配重了 = 浏览器会掐）

静态托管首页也要返回 200。

### ★ 必须能区分两种 404（长得像，根因完全不同）

| 返回体形状 | 含义 | 修哪儿 |
|---|---|---|
| `{"code":"INVALID_PATH","requestId":...}` | **网关**路由没绑 | 控制台配网关路由 |
| `{"ok":false,"error":"not found","receivedPath":"/api/xxx"}` | **函数**里少注册分支 | 改 `functions/api/index.js` |

这两种报错后修的位置完全不同。检查项只报「404」等于没报，必须归类。

### 硬边界（不许越界）

- **只发 GET**，绝不发 POST / PATCH / DELETE。
  理由一：避免污染数据库。理由二：本仓库 7篇已过审帖全被收藏过，再触发收藏会撞唯一索引 409。
- **不改任何线上数据**，只探活。
- **静态托管 URL 每次重部署都会变**——跑之前先确认 `public/*.html` 里写死的那个是当前有效的，别拿旧URL 报假警。

## 失败时怎么办

1. 先报告**失败现象原文 + 归类到哪一类**（C1 哪种泄漏 / C2 哪种 404），等用户确认
2. 用户同意后再动手修
3. **修完必须重新完整跑一轮**——不能只重跑失败那一项。C1 改了文件要重扫全仓库；C2 改了代码要重新部署再探活
4. 修完在 `RUN_LOG.md` 追加一条记录，**不要覆盖历史**
