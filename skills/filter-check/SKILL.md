# 首页分类筛选检查（filter-check）

检查对象：`public/index.html` 的分类筛选交互（右栏 chip 按钮点击 → 中栏卡片列表过滤）。

## 前置条件

1. 本地服务器已启动：在项目根目录运行 `node server.js`（端口以 server.js 内配置为准）。
2. 浏览器能打开首页 `http://localhost:端口/`，页面加载成功（能看到帖子列表、热门榜、分类三栏）。

## 测试步骤与通过标准

三种情况必须全部测完，每种都停下核对结果，不许跳过。

### 情况一：有结果（正常筛选）

1. 打开首页，先记下「全部」按钮上的帖子总数 N。
2. 点击一个**帖子数 ≥ 1** 的分类（从右栏按钮上的数字判断，比如「职场新人 (3)」）。
3. **通过标准（全部满足才算过）**：
   - 中栏只剩该分类的帖子，数量与该按钮上标的数字一致；
   - 每张卡片的分类徽章显示的就是所点分类；
   - 被点的按钮呈选中态（高亮/active 样式），其余按钮恢复普通态；
   - 左栏热门榜**不受筛选影响**，仍是全站前 5。

### 情况二：无结果（空分类）

1. 点击一个**帖子数为 0** 的分类（按钮上标 (0) 的那个；若六个分类都有帖子，则视为本情况当前无法测试，在记录里注明即可）。
2. **通过标准**：
   - 中栏不显示任何卡片，也不显示空白/破版；
   - 出现友好的空状态提示框（含所点分类名，如「xx 还没有帖子」），不能是报错。

### 情况三：清空恢复（回到全部）

1. 在情况一或二的状态下，点击「全部」按钮。
2. **通过标准**：
   - 中栏恢复显示全部 N 张卡片（与最初记下的数字一致）；
   - 「全部」按钮呈选中态，其他按钮取消选中；
   - 卡片内容与初次加载时完全一致（顺序、数量、徽章都对）。

## 附加检查（顺手核对，不算单独情况）

- 各分类按钮上标的数字之和 + 「未分类」帖子数 = 全部帖子数 N（数字对不上说明 posts.json 数据或计数逻辑有问题）。
- 连续快速切换分类两三次，列表内容与选中态始终跟随，无残留、无卡死。

## 可访问性检查（Day 12 余力加练加入，每次调用都要测）

1. **键盘可达**：不用鼠标，纯 Tab 键能聚焦到每个分类按钮（它们是原生 `<button>`，天然可聚焦）；按 Enter 能触发筛选，效果与鼠标点击完全一致（列表过滤 + 选中态切换）。
2. **焦点可见**：按钮聚焦时必须有可见的焦点指示（浏览器默认 outline 或等效替代样式）；页面里允许 `outline: none`，但只准用在配了替代聚焦样式（如变色描边 + 光晕）的元素上，裸删 outline 不合格。
3. **对比度**：选中态分类按钮的文字/背景、空状态提示框的文字/背景，对比度 ≥ 4.5:1（WCAG AA 正文标准）。测试方法：读元素 computed style 的 color 与 backgroundColor，按 WCAG 相对亮度公式算比值。
4. 焦点保持（Day 12 修复后新增标准）：点击分类按钮触发重渲染后，键盘焦点必须留在重渲染后的同一分类按钮上（不能丢回 body）。已在 index.html 的 renderCats 点击处理里实现（focus + preventScroll），鼠标与键盘两条路径都要测。

## 失败时怎么办

- 任何一条不通过：先报告失败现象和可能原因，等用户确认后再动手修，修完必须重新完整跑一轮（三种情况都要重测，不能只重测失败的那种）。
